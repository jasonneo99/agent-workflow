# Historical reconciliation

Expired write reservations stay pending or uncertain. A deterministic stale-preimage, malformed-hunk or exact context/removal diagnostic rejection can establish that the exact bound patch never reached its write syscall. The reconciliation operation requires the complete original request, matching request key, authenticated rejection and receipt chain, one unambiguous interval ending at the next same-target claim, quiescent terminal work, explicit human authorization and a fresh exact runtime/history-reconciliation/<run-id> intent. It appends proof without changing reservation status or replaying the effect. Archive revalidates proof at its boundary. Unknown I/O failures and ambiguous attempts remain unresolved. An earlier overlapping expired claim is excepted only after its own authenticated no-effect observation proves rejection strictly before the later claim; temporal recursion is bounded and cycles fail closed. Completed terminal attempts may receive the same no-effect observation without changing their status or acceptance.

An obsolete policy contract may be explicitly retired from actionable views using a separate runtime/policy-disposition/<run-id> intent. The operation freezes the historical task digest, requires independently accepted current-policy evidence, locks its explicit same-project family, rejects active or queued children, tasks, approvals and coordinator ownership, and rejects family effects without independently authenticated no-effect observations, and atomically appends separately bound obsolete-policy-unaccepted dispositions for the exact terminal family members. Every member retains its own task, status and receipt chain. A newly active or queued member becomes visible; retiring a parent never hides an unbound child. It never marks the historical requirements satisfied or rewrites old runs.

These operations require normal runtime adoption and review before live use. Source tests alone do not authorize installed-runtime mutation.

Maintained storage entrypoints are `reconcileRejectedWrite` and `retireObsoletePolicy`; their `OnClient` forms support a caller-owned transaction and rollback validation. They require a retained direct-human prerequisite authorization artifact with its exact audit receipt. Exact repeated observations return their existing artifact; a changed proof or decision never replaces history. Archive and restore revalidate the no-effect proof at their own boundary, with consistent project-before-row locking.

Candidate preparation copies a verified installed baseline into a new artifact, compiles only the reviewed delta, and packages the reviewed core through the maintained npm tarball path. Fresh plugin dependency installation can change unrelated library versions: reject that candidate if it differs from the reviewed baseline. A separately reviewed bounded standalone candidate may copy the exact baseline external dependencies when dependency declarations remain unchanged and bytes, modes and symlink targets are verified before and after preparation. The YAML bundle manifest does not cover JavaScript payload bytes: also verify the full runtime tree manifest, package integrity, runtime archive hash and exact delta hashes. Do not alter an installed plugin, rewrite an old manifest, self-sign, or promote unrelated dirty source to make a candidate appear trusted. Source validation is separate from runtime adoption and product acceptance.

Useful training evidence includes preserving an obsolete contract as unaccepted, recovering exact historical requests instead of inventing preimages, distinguishing deterministic pre-write errors from uncertain effects, and testing JSONB-canonical idempotency. Recording such evidence does not export or promote training material.

A standalone operational candidate does not update installed queue readers. New disposition labels need explicit reader adoption before claiming all global surfaces reflect retirement. Keep that release gate separate from successful bounded history reconciliation.

Receipt agent IDs are registered execution principals. Human display names belong in decision metadata (`actor` or `requestedBy`); history authorization, rejection reconciliation and policy retirement audit as `workflow-orchestrator`. The PostgreSQL fixtures retain the production agent foreign key so an unregistered human name cannot accidentally become an audit-agent ID.

Policy retirement requires full receipt coverage for every exact family member, including completed historical children. A valid root chain cannot compensate for an unchained child. Legacy gaps stay visible as gaps; never backfill hashes or rewrite earlier receipts.

A defective view retirement can be corrected with `invalidateObsoletePolicy` under a fresh exact policy-disposition intent. It independently checks the bound unchanged member snapshots, the exact original retirement receipts, the root audit chain, retained defect evidence and each member's current full-chain result. Its append-only report records invalid results without repairing them. Repeating the exact request returns the same observation; changed bindings fail. This correction restores visibility only when the corresponding reader is adopted and requires a separate manual-reconciliation admission hold. It grants no execution authority, acceptance, grant refund or permission to retire incomplete history. Other archival decisions remain independently bound.

## Reader-owner corrective handoff (adoption held)

Add one authenticated invalidation predicate with these exact bindings: root artifact kind `obsolete_policy_disposition_invalidation`; content disposition `invalidated-policy-retirement`; content `projectId` equals the candidate run project; `executionAuthorityGranted=false`, `manualReconciliationRequired=true`, `viewOnly=true`; root receipt action `obsolete_policy_disposition_invalidated`, identical metadata and non-null receipt hash; original disposition artifact URI equals invalidation `dispositionUri`; original disposition belongs to that same root/project; memberReport contains candidate run ID and the exact original retirement receipt ID/hash/artifact URI. The original retirement receipt must still bind the member's task, project and original disposition (root URI or child parentDispositionUri). Artifact/receipt deletion or mismatch must fail closed.

Presentation ignores only the matching retired-policy hide receipt when this bound invalidation exists, preserving all unrelated human archive/supersession receipts. Exact-source admission adds `AND NOT authenticated_policy_invalidation(run)` as a manual-reconciliation hold; visibility never supplies execution authority. The hold remains bound to member identity and invalidated retirement even if later task/status drift makes the history visible. Preserve existing queued/running member visibility and all original active-work/effect checks. Test unchanged root plus blocked child, changed task/status, missing/mismatched artifact or receipt, duplicate observation, and an unrelated human archive that must remain hidden. Installed readers and the bounded corrective write-only candidate do not include this reader change.
